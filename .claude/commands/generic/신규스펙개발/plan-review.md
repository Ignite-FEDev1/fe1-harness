완전성 — 기획서와 1:1 대조하며 확인:
□ 기획서에 있는 모든 화면이 plan.md에 반영되어 있다
□ 기획서에 있는 모든 기능이 plan.md에 반영되어 있다

□ API 연동 범위(엔드포인트명, 요청/응답 필드)가 명시되어 있다
□ 미확정/TBD 사항이 명시되어 있다

작업 방식 반영:
□ 비즈니스 로직 우선 작업 전략이 명확히 반영되어 있다
□ mock API → 실 API 교체 전략이 명시되어 있다
□ 마크업 적용 전략이 명시되어 있다 (3가지 케이스 중 해당 케이스와 이유)

구체성:
□ FE 작업 항목이 실제 구현 가능한 수준으로 구체적이다 (추상적인 "개발" 같은 표현 없음)
□ 예상 파일 경로가 명시되어 있다 (코드베이스 분석이 이루어진 경우)
