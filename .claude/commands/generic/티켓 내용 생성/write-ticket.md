## 역할
두서없이 작성된 작업 내용을 정리하여 Jira 티켓에 바로 붙여넣을 수 있는 형태로 산출합니다.

## 입력
- `{DOCS_DIR}/session.md` — 작업 내용과 티켓 접두어

## 작업 지침

### 1단계: 코드베이스 확인

코드베이스 경로 결정 (우선순위):
1. session.md의 `pipeline_inputs.project_path` (사용자가 직접 입력한 경로)
2. session.md의 `project_path` (설정에서 선택한 프로젝트)
3. 둘 다 없으면 → 코드베이스 분석 건너뜀

코드베이스 경로가 존재하면:
- 입력된 작업 내용과 관련된 코드를 Glob, Grep, Read 도구로 파악
- 수정 대상 파일/컴포넌트 위치
- 기존 패턴 (유사 기능이 이미 구현되어 있는지)
- 작업 범위 추정에 필요한 구조 파악

간단한 작업이라면 최소한의 탐색만 수행합니다.

### 2단계: 정리 및 작성

공수 산정 기준:
- 코드베이스의 기존 패턴 활용 가능 여부 반영
- 1d = 하루 (8시간 기준), 0.5d 단위로 산정
- 단순 수정/적용: 0.5d, 신규 컴포넌트/로직: 1~2d, 여러 페이지 적용: 1.5~2d

## 산출물

`{DOCS_DIR}/ticket.md`:

```
### {TICKET_PREFIX} 티켓 제목

공수: Nd

#### 설명
한 줄 요약

#### 상세 내용
- 구체적인 작업 항목 나열
- 관련 파일 경로 참조 (코드베이스에서 파악한 경우)
- 기획 조건/정책 반영

#### AC (인수 조건)
- [ ] 체크리스트 형태의 완료 기준
- [ ] ...
```

## 출력 규칙
- Confluence/Jira에 붙여넣었을 때 스타일이 적용되는 마크다운 형식
- 인라인 볼드 `**` 사용 금지, heading `####` 사용
- 어투: 명확한 업무 문체
- 입력이 두서없어도 작업 목적과 범위를 명확히 정리
- 불명확한 부분은 "확인 필요 사항"으로 질문 추가

## 티켓 품질 기준 (필수)
1. **담당자가 아닌 다른 팀원이 읽어도 작업 내용을 정확히 이해할 수 있어야 함**
   - "왜 이 작업이 필요한지" (배경)를 반드시 포함
   - 약어나 암묵적 맥락에 의존하지 말고, 처음 보는 사람도 이해할 수 있게 작성
   - 관련 화면/기능의 위치나 진입 경로를 명시 (예: "마이페이지 > 설정 > 알림 설정 화면")

2. **이 티켓 내용만 복사해서 Claude에게 붙여넣으면 정확한 구현이 가능해야 함**
   - 상세 내용에 구현에 필요한 모든 정보를 포함 (기획 조건, 동작 규칙, 예외 케이스)
   - 수정 대상 파일 경로, 참고할 기존 패턴을 구체적으로 명시
   - AC(인수 조건)가 코드 검증 가능한 수준으로 구체적이어야 함 (추상적 표현 금지)
   - 외부 문서 참조 없이 티켓 자체만으로 완결되어야 함
