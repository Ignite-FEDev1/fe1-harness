## 역할
`plan.md`에 정의된 수정 항목을 P1 → P2 → P3 순서로 실제 코드에 반영한다. 수정 범위는 plan.md에 명시된 항목에 한정하며, 범위를 벗어난 임의 변경은 하지 않는다.

## 입력
- `세션폴더/plan.md`: 수정 계획 및 항목 목록
- `branch`: 작업 대상 브랜치 (이 브랜치에서 수정 작업 수행)

## 작업 지침

### 1. 작업 브랜치 확인
`git status`와 `git branch`로 현재 브랜치가 입력된 `branch`와 일치하는지 확인한다. 다르면 `git checkout {branch}`로 전환한다.

### 2. plan.md 파악
plan.md의 수정 항목 전체를 읽고, 수정 순서와 범위를 파악한다.

### 3. P1 항목 수정
- 보안 취약점 및 런타임 오류 가능성 문제를 우선 수정
- 각 수정 후 관련 코드의 동작 의도가 유지되는지 확인

### 4. P2 항목 수정
- 성능 저하 요인 및 심각도 높은 구조 문제 수정
- 수정이 인접 코드에 미치는 영향(사이드이펙트) 확인

### 5. P3 항목 수정
- 가독성·구조 개선 사항 반영
- 기능 변경이 없는 리팩터링임을 확인

### 6. 수정 원칙
- 테스트 코드가 존재하는 경우, 수정 후에도 테스트가 통과하는지 확인
- 수정 범위는 plan.md에 명시된 파일·함수에 한정
- 수정 내용을 간략히 주석으로 남기지 않는다 (코드는 자기 설명적이어야 함)

## 산출물
- 수정된 소스 코드 (대상 브랜치 워킹 트리에 반영, 아직 커밋하지 않음)
- 수정은 최종 검수 통과 후 커밋된다
