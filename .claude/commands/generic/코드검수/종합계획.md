## 역할
이전 단계에서 생성된 모든 `review-*.md` 파일을 읽고, 중복·유사 문제를 통합하여 실행 가능한 수정 계획을 단일 `plan.md`로 작성한다.

## 입력
- `세션폴더/review-simplify.md` (존재하는 경우)
- `세션폴더/review-clean-code.md` (존재하는 경우)
- `세션폴더/review-security.md` (존재하는 경우)
- `세션폴더/review-performance.md` (존재하는 경우)
- `세션폴더/review-type-safety.md` (존재하는 경우)
- `세션폴더/review-accessibility.md` (존재하는 경우)

## 작업 지침

### 1. 리포트 수집
세션 폴더에서 `review-*.md` 파일을 모두 읽는다.

### 2. 문제 목록 통합
- 동일한 파일·라인에서 여러 관점이 지적한 문제는 하나로 병합한다
- 각 문제에 출처 관점(들)을 명시한다

### 3. 우선순위 분류
- **P1 (즉시 수정)**: 보안 취약점 전체, 런타임 오류 가능성이 있는 타입 문제
- **P2 (수정 권장)**: 성능 저하 요인, 심각도 높음으로 분류된 클린코드·접근성 문제
- **P3 (개선 권장)**: 심각도 중간/낮음의 가독성·구조 개선, Simplify 제안

### 4. 수정 계획 작성
각 수정 항목에 대해 구체적인 수정 방향을 기술한다. 코드 예시가 도움이 되는 경우 포함한다.

### 5. 검수 기준 정의
최종 검수 단계에서 사용할 통과 기준을 명시한다:
- P1 문제 0건
- P2 문제 80% 이상 해결
- 전체 문제 해결률 70% 이상
- 수정으로 인한 신규 문제 없음

## 산출물
`세션폴더/plan.md`

```
# 코드 검수 수정 계획

## 검토 대상
- 브랜치: {branch}
- 검토 커밋 범위: {commit_hashes 또는 "브랜치 전체 diff"}
- 실행된 검수 관점: {활성화된 관점 목록}

## 검수 기준 (최종 검수 통과 조건)
- P1 문제: 0건
```
