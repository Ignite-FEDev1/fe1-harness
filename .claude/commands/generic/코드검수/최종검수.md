---

## 역할
코드 수정 전/후를 비교하고 `plan.md`의 검수 기준에 따라 통과 여부를 판정한다. 기준 미달 시 직접 재수정하며 최대 3회까지 루프를 반복한다. 통과 시 결과를 브랜치에 커밋하고 최종 리포트를 작성한다.

## 입력
- `세션폴더/plan.md`: 수정 계획 및 통과 기준
- `branch`: 결과를 커밋할 브랜치
- 수정된 소스 코드 (브랜치 워킹 트리)

## 작업 지침

### 1. 베이스라인 diff 추출
```
git diff HEAD  # 현재 워킹 트리의 모든 변경사항
```
이 diff가 이번 코드 수정의 전체 범위다.

### 2. 검수 수행 (루프, 최대 3회)

#### 2-1. plan.md 기준 항목 점검
plan.md의 각 수정 항목을 순회하며 반영 여부를 확인한다:
- P1 항목: 전수 확인 (누락 시 즉시 재수정)
- P2 항목: 반영률 계산
- P3 항목: 반영률 계산

#### 2-2. 사이드이펙트·동작 변경 점검
diff를 분석하여 다음을 확인한다:
- plan.md에 없는 파일 변경이 있는가?
- 함수 시그니처·반환값이 의도치 않게 변경되었는가?
- 조건 분기·예외 처리가 제거 또는 우회되었는가?
- 외부 인터페이스(props, API, 이벤트)가 변경되었는가?

#### 2-3. 점수 산출
```
P1 미해결 건수: N건
P2 해결률: X%
전체 해결률: Y%
신규 문제(사이드이펙트) 건수: Z건
```

#### 2-4. 통과 기준 판정
plan.md에 명시된 기준:
- P1 문제 0건 ✅/❌
- P2 해결률 80% 이상 ✅/❌
- 전체 해결률 70% 이상 ✅/❌
- 신규 문제 0건 ✅/❌

**모두 ✅** → 통과, 3단계로 이동  
**하나라도 ❌** → 미달 항목 수정 후 루프 반복 (최대 3회)

#### 2-5. 재수정 (미달 시)
- 미달 원인이 된 항목만 타깃 수정
- 수정 후 2-1부터 재실행
- 3회 초과 시 루프 중단, 미달 상태로 최종 리포트 작성 후 커밋

### 3. 최종 커밋
통과(또는 3회 소진) 후:
```
git add -p  # 변경된 소스 파일만 스테이징
git commit -m "검수: {branch} 코드 검수 반영"
```
세션 폴더의 .md 파일들은 커밋에 포함하지 않는다.

### 4. 최종 리포트 작성
`세션폴더/final-report.md`를 생성한다.

## 산출물

### 브랜치 커밋
검수 후 변경된 코드가 `{branch}`에 새 커밋으로 추가됨

### `세션폴더/final-report.md`
```
# 코드 검수 최종 리포트

## 검수 개요
- 브랜치: {branch}
- 검수 일시: {datetime}
- 최종 결과: 통과 / 조건부 완료 (3회 소진)
- 검수 반복 횟수: {N}회

## 점수 요약
| 기준 | 목표 | 결과 | 판정 |
|------|------|------|------|
| P1 미해결 | 0건 | N건 | ✅/❌ |
| P2 해결률 | ≥80% | X% | ✅/❌ |
| 전체 해결률 | ≥70% | Y% | ✅/❌ |
| 신규 문제 | 0건 | Z건 | ✅/❌ |

## 반영된 수정 항목
(plan.md 항목별 반영 여부 요약)

## 미반영 항목 및 사유
(있는 경우)

## 감지된 사이드이펙트
(있는 경우)

## 참고 산출물 (세션 폴더)
- review-simplify.md / review-clean-code.md / review-security.md 등
- plan.md
- final-report.md (이 파일)
```
