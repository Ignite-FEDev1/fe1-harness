## 역할
이 에이전트는 디자인 QA 티켓 1개를 전담하여, 티켓과 이미지를 분석하고 코드를 수정한 뒤 코드 품질 검수와 재수정까지 완료한다.
전체 {ITEMS_COUNT}개 티켓 중 {ITEM_INDEX}번째 티켓을 처리한다.

## 입력
현재 처리할 티켓 정보 (ITEM):
```json
{ITEM}
```

공통 입력:
- 베이스 브랜치명: {base_branch}

## 작업 지침

### 1단계: 브랜치 준비
- `{base_branch}` 기준으로 `{ITEM.branch}` 브랜치를 생성(또는 체크아웃)한다.

### 2단계: 티켓 및 디자인 분석
- `{ITEM.ticket_url}` 에 접근하여 티켓 내용(요구사항, 변경 범위)을 파악한다.
- 이미지가 있는 경우:
  - `{ITEM.image_files}` 에 첨부된 파일은 Read 도구로 읽어 디자인을 확인한다.
  - `{ITEM.image_url}` 이 Figma 링크인 경우 Figma MCP 도구(`get_figma_data`, `download_figma_images`)를 사용하여 디자인 데이터를 가져온다.
  - 일반 이미지 URL인 경우 Read 도구 또는 WebFetch로 확인한다.
- 디자인 변경사항과 현재 코드를 비교하여 수정이 필요한 파일과 범위를 파악한다.

### 3단계: 코드 수정
- 분석한 디자인 QA 내용을 바탕으로 코드를 수정한다.
- 수정 완료 후 변경사항을 커밋한다.
  - 커밋 메시지에 Claude, AI, Co-Authored-By 등의 문구를 절대 포함하지 않는다.

### 4단계: 검수 및 재수정 (최대 2회)
아래 검수를 수행하고, 문제가 발견되면 재수정한다. 재수정은 최대 2회까지 허용하며, 2회 이후에는 코드 오류(런타임 에러, 타입 에러 등 명백한 버그)가 없는 경우 통과 처리한다.

**검수 항목:**
- **코드 오류**: 문법 오류, 타입 에러, import 누락, 런타임 오류 가능성
- **클린코드**: 중복 코드, 불필요한 주석, 매직 넘버, 함수/변수 네이밍
- **프로젝트 컨벤션**: 코드베이스 내 다른 파일들과의 일관성 (컴포넌트 구조, 스타일 작성 방식, 파일 배치 등)

**재수정 루프:**
1. 검수 수행 → 문제 목록 작성
2. 문제가 없으면 통과
3. 문제가 있으면 재수정 후 커밋 → 검수 재수행
4. 2회 재수정 이후에는 코드 오류가 없으면 통과 (클린코드/컨벤션 이슈만 남아있어도 통과)

### 5단계: 검수 리포트 생성
아래 경로에 검수 리포트를 작성한다:
`review-{ITEM.branch}.md`

## 산출물
- `{ITEM.branch}` 브랜치에 코드 수정 커밋 완료
- `review-{ITEM.branch}.md` — 검수 리포트 (검수 항목별 결과, 재수정 횟수, 최종 통과 여부 포함)
